# Адмін-панель

Вхід: `/login` акаунтом з роллю STAFF або ADMIN → `/admin`. Захист у 3 шари: middleware, `requireAdminPage()` у layout/сторінці, `requirePermission()` у кожній Server Action.

## Ролі

| Можливість | STAFF | ADMIN |
|---|:-:|:-:|
| Огляд, замовлення (перегляд, статуси, ТТН, нотатки) | ✔ | ✔ |
| Товари: створення / редагування / дублювання / деактивація | ✔ | ✔ |
| Видалення товару | — | ✔ |
| IMEI / serial / закупівля вживаних (перегляд і запис) | ✔ | ✔ |
| Модерація відгуків | ✔ | ✔ |
| Клієнти (перегляд) | ✔ | ✔ |
| Повернення коштів через LiqPay | — | ✔ |
| Промокоди, налаштування, журнал дій, ролі користувачів | — | ✔ |

Першого адміна створює `npm run db:seed`. Далі ролі змінює ADMIN у розділі «Клієнти» (себе змінити не можна).

## Товари

Товар → **варіанти** (пам'ять, колір, стан, SIM, ціна, залишок, гарантія). Ціни вводяться в гривнях (`12 999` або `12999,50`) і зберігаються в копійках. «Залишок» — фізична кількість; резерв під незавершені замовлення показується поруч і не перезаписується.

### Вживаний пристрій (стан ≠ «Новий»)

Кожен фізичний екземпляр — окремий варіант зі складом 1. У формі:
* **Публічні** дані (бачить клієнт): батарея %, цикли, клас, корпус, екран, функції (Face ID, камери, True Tone, …), комплектація, гарантія, недоліки, коментар майстра.
* **Приватні** дані (лише персонал): IMEI (перевірка Luhn), серійний номер, закупівельна ціна, постачальник, джерело, нотатки, чек-ліст тестування. Зберігаються зашифрованими (AES-256-GCM) в окремій таблиці; дублікати IMEI/serial відхиляються.
* **Фото саме цього пристрою**: вкладка «Фото» → для кожного зображення оберіть цей варіант у випадаючому списку. На сторінці товару для обраного екземпляра спершу показуються його фото.
* Статус пристрою (`DRAFT → IN_TESTING → READY → RESERVED → SOLD / RETURNED`): у продаж потрапляють лише не-`DRAFT`. Після продажу останньої одиниці статус автоматично `SOLD`; при поверненні/скасуванні — `READY`.

Кожен перегляд розшифрованих IMEI/serial (сторінка товару, замовлення) записується в журнал: `usedDevice.secret_view`.

### Фото

Drag-and-drop у Cloudinary (підпис створює сервер; секрет не потрапляє в браузер). Перегляд, порядок (▲▼), головне (★), alt-текст, видалення. Приймаються лише URL вашого Cloudinary-акаунта. Без Cloudinary можна вставити посилання на зображення вручну (лише `res.cloudinary.com` або `/images/…`).

## Замовлення

Статуси: `PENDING → PAYMENT_PENDING → PAID → PROCESSING → PACKED → SHIPPED → DELIVERED`, а також `CANCELLED`, `REFUNDED`, `RETURN_REQUESTED`, `RETURNED`. Допустимі переходи обмежені (`src/lib/order-status.ts`); UI пропонує тільки їх, сервер перевіряє знову.

* Онлайн-оплату («PAID») підтверджує тільки платіжна система — вручну поставити не можна.
* Післяплата / оплата при отриманні: склад «продається» при переході в `PROCESSING`.
* Скасування: неоплачене → резерв звільняється; оплачене → товар повертається на склад, кошти повертає кнопка «Повернути кошти» (ADMIN).
* «Створити ТТН Нової пошти» (див. NOVA_POSHTA.md); «Додати ТТН вручну» для кур'єрських.
* Оплата після скасування / невідповідність суми → історія містить запис `payment_alert` і надсилається лист адміну.

## Промокоди

Відсоток або фіксована сума, мінімальне замовлення, період дії, загальний ліміт, ліміт на клієнта, обмеження за товарами (ID) та категоріями. Лічильник використання збільшується атомарно під час оформлення замовлення.

## Відгуки

Залишити відгук може лише клієнт із **доставленим** замовленням цього товару (перевіряється на сервері); відгук потрапляє на модерацію; рейтинг товару перераховується при схваленні.

## Налаштування

Магазин (назва, юр. дані, контакти, соцмережі), Оплата (перемикачі способів, передоплата/комісія післяплати), Доставка, Замовлення (час резерву, ліміти), Гарантія, SEO, Аналітика (GA4/GTM/Pixel), Головна, Email. Секрети (ключі LiqPay/НП/пошти/Cloudinary) — **лише змінні середовища**; сторінка показує тільки статус «задано / не задано» та попередження, якщо увімкнений sandbox.
